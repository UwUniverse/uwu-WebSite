# uwu_kernel build system

`uwu_kernel` is the Soong module type provided by uwuAOSP. It does not replace Linux
Kbuild; it converts Android-side kernel orchestration from global Make variables and
implicit rules into Soong module dependencies.

## Why uwu_kernel is needed

The core of Soong-only is skipping Kati's Android target-generation phase. If the kernel
is still built only through the legacy `vendor/uwu/build/tasks/kernel.mk`, the input and
output relationships for the kernel image, DTB, DTBO, modules, and UAPI headers remain
implicit Make rules. Soong and fsgen cannot reliably add those artifacts to their
dependency graph.

`uwu_kernel` declares the Android-side kernel build as a Soong module, allowing Soong to
see:

- kernel source, configuration, and toolchain inputs;
- kernel image, DTB, DTBO, module, and UAPI-header outputs;
- dependencies between external modules, install manifests, and partitions.

fsgen can then consume module outputs directly and generate boot, DTBO, super, and vbmeta
images without depending again on kernel targets generated by Kati. This preserves the
complete Android build dependency graph after Kati is skipped.

Source builds still call Linux Kbuild from a Soong action; `prebuilt` mode does not call
Kbuild. If prebuilt mode must continue to provide configuration, headers, or module
outputs, declare the corresponding `prebuilt_config`, `prebuilt_headers`, and
`prebuilt_modules` properties as well.

The official Soong documentation states that the goal of Soong-only is to reduce
build-analysis time by about half and improve developer efficiency. `uwu_kernel` is part
of the kernel migration needed for that goal: it skips legacy Make orchestration on the
Android side while Soong still invokes Linux Kbuild for the actual kernel compilation.

## Responsibility boundaries

| Layer | Responsibility |
| --- | --- |
| `uwu_kernel` | Declare inputs and outputs, prepare the toolchain, call Kbuild, and export headers and images |
| Linux Kbuild | Run Kconfig, compile the kernel, and generate DT and modules |
| `fsgen` | Consume kernel outputs and create Android boot, DTBO, super, and vbmeta images |
| Device tree | Select source, defconfig, fragments, DT strategy, and module install manifests |
| Kernel tree | Maintain source, Kbuild, DTS, defconfig, and UAPI |

Migration does not require, and should not attempt, to rewrite kernel-source Makefiles as
Android.bp. Soong is responsible only for calls and dependency declarations in the
Android build graph.

## Minimal configuration

```bp
uwu_kernel {
    name: "kernel",
    kernel_dir: "kernel/vendor/device",
    kernel_arch: "arm64",
    image_name: "Image",
    clang_version: "clang-r<version>",
    config: {
        defconfig: "gki_defconfig",
        fragments: ["vendor/device.config"],
    },
}
```

When `clang_version` is unset, the AOSP Clang version exported by envsetup is inherited.
Set `autofdo_profile` and `rbe_wrapper` when AutoFDO or RBE is needed; both affect only
source kernels.

Select the module during the BoardConfig stage:

```make
BOARD_USES_SOONG_KERNEL := true
SOONG_KERNEL_MODULE := //device/<vendor>/<device>:kernel
```

Add it to the product install set:

```make
PRODUCT_PACKAGES += kernel
```

## Design principles

- Devices consume kernel artifacts by module name and output labels, not `.intermediates` paths;
- common build logic belongs in `vendor/uwu/build/soong/kernel`, while device differences stay in Android.bp;
- kernel source is tracked through directory dependencies, rather than expanding the entire source tree into `srcs`;
- kernel, DT, modules, and UAPI headers must all have explicit dependencies in the Soong graph;
- the legacy Make path remains a compatibility path for unmigrated devices, and new device-specific exceptions should not be added there.
