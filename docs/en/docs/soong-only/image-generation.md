# Soong-only image generation

## Component responsibilities

| Component | Main responsibility |
| --- | --- |
| `build/make/core/soong_config.mk` | Export partition, boot, and AVB parameters |
| `build/soong/fsgen` | Create image modules and dependencies from product variables |
| `build/soong/filesystem` | Implement filesystem, bootimg, DTBO, vbmeta, and related modules |
| `android_device` | Collect device dependencies and copy results to `PRODUCT_OUT` |
| `ninja` | Execute the commands in the rules generated by Soong |

## Filesystem partitions

fsgen uses `PartitionQualifiedVariables` to determine which partitions need to be
generated. Common partitions include `system`, `system_ext`, `product`, `vendor`, `odm`,
`userdata`, `system_dlkm`, `vendor_dlkm`, `odm_dlkm`, and `recovery`.

Each filesystem module first creates a staging directory, then generates an image from
the partition filesystem and AVB configuration. Dynamic-partition products pass their
active partitions to the `super` image module; vbmeta modules consume the outputs and
public-key information provided by partition modules.

## Boot images

fsgen creates boot-class images from the following inputs:

- the default output of the kernel module selected by `SOONG_KERNEL_MODULE`;
- the kernel module's `.dtb` output;
- `ramdisk`, `vendor_ramdisk`, or the recovery filesystem;
- boot header version, partition size, kernel command line, and bootconfig;
- AVB key, algorithm, rollback index, and security patch for the corresponding partition.

`android_device` then copies module outputs to:

```text
$(PRODUCT_OUT)/boot.img
$(PRODUCT_OUT)/init_boot.img
$(PRODUCT_OUT)/vendor_boot.img
$(PRODUCT_OUT)/vendor-bootconfig.img
```

`vendor_kernel_boot.img` appears only when the `vendor_kernel_boot` partition is enabled
and its corresponding module is created.

## DTB and DTBO

`uwu_kernel` can provide `.dtb` and `.dtbo` outputs. In Soong-only mode, fsgen can read
DTBO from a kernel module label:

```text
:kernel{.dtbo}
```

Devices can also provide a prebuilt DTBO through `BOARD_PREBUILT_DTBOIMAGE`. DTBO page
size, AVB parameters, and output name come from partition configuration. The DTBO module
provides output to vbmeta and installs it into Soong's `etc` output directory;
`android_device` copies the final image to `PRODUCT_OUT/dtbo.img`.

Common QCOM flow:

1. Kbuild generates multiple DTB/DTBO files;
2. `merge_dtbs.py` merges and organizes the device tree;
3. `mkdtboimg create --page_size=<size>` generates the DTBO image;
4. fsgen connects DTB/DTBO to the boot, DTBO, and vbmeta dependencies.

## AVB and super

Each AVB-enabled partition gets its key, algorithm, rollback index, and footer parameters
from `PartitionQualifiedVariables`. fsgen creates partition AVB metadata, while vbmeta
modules build chained dependencies from the `vbmeta_*` partition lists.

Dynamic-partition dependencies usually look like this:

```text
system/product/vendor/odm/... filesystems
                |
                v
              super
                |
                v
          vbmeta_system/vendor
                |
                v
              vbmeta
```

Do not copy this dependency graph manually in device configuration. Set the correct
BoardConfig variables and let fsgen create the modules from product configuration.

## Product output

The product output directory is usually `out/target/product/<device>`. Common outputs
include:

| Output | Description |
| --- | --- |
| `kernel` | Default kernel image output from `uwu_kernel` |
| `dtb.img` | Device-tree image; merging depends on device configuration |
| `dtbo.img` | DTBO image; page size comes from product configuration |
| `boot.img` | Boot image |
| `init_boot.img` | init_boot image |
| `vendor_boot.img` | Vendor boot image |
| `system.img`, `vendor.img`, `product.img` | Dynamic-partition member images |
| `super.img` | Dynamic-partition container image |
| `vbmeta*.img` | AVB chain images |

Special images such as `boot_16k.img` and `vendor_kernel_boot.img` are generated only
when the corresponding product partition and kernel configuration are enabled. Missing
an image for a disabled partition does not mean the Soong-only build failed.
